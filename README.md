# Van Inventory

Work-van parts inventory as an installable web app (PWA): scan a barcode to take
parts off the van or add stock, see which shelf a part lives on, run the quarterly
count shelf by shelf, and export everything to Excel. All data is stored **on the
phone** (IndexedDB) — the web host only serves the app files.

## Run locally

Any static server over `http://localhost` works (camera + install need a secure
context; localhost counts):

```
npx --yes http-server . -p 8124 -c-1
```

Open http://localhost:8124/?nosw=1 while developing — the `nosw=1` flag keeps the
service worker from caching stale files. If you ever loaded the app *without* the
flag, unregister the worker and clear site data before testing edits (DevTools →
Application), or the old files keep being served.

Console helpers (DevTools):

- `__importFile('local/van.xlsx')` — import a spreadsheet served from this folder
  (`local/` is git-ignored; keep inventory files there, never in the repo).
- `__scan('843122104825')` — feed a code to the scan screen as if the camera saw it.
- `__stats()` — record counts per store and per location.
- `__resetAll()` — wipe everything and re-seed the shelves.

`node tools/import-check.mjs "path\to\sheet.xlsx"` runs the importer's parser
over a spreadsheet and prints the preview numbers without a browser.

## Deploy ritual (every update)

1. Edit files.
2. **Bump `VERSION` in `sw.js`** and `APP_VERSION` in `js/app.js` — phones only
   fetch new files when the worker version changes.
3. If you added a file, add it to `ASSETS` in `sw.js`.
4. Add a `CHANGELOG.md` entry, commit, `git push`. GitHub Pages redeploys `main`.
   Installed phones show an "Update ready" toast on the next launch.

## Vendor lock (do not "just update one file")

`vendor/barcode-detector/ponyfill.js` (barcode-detector 3.2.1) is built against
`vendor/zxing/zxing_reader.wasm` (zxing-wasm **3.1.1**). Update them **together**
or decoding breaks. SheetJS lives at `vendor/sheetjs/xlsx.full.min.js` (0.20.3).
`vendor/package.json` marks that folder CommonJS so node scripts can `require()`
the SheetJS bundle while the app itself is ES modules.

## Same-origin note

This app is hosted on `modzer627.github.io` next to other PWAs. It uses its own
IndexedDB name (`van-inventory`), its own cache prefix (`van-inventory-`), and its
service worker only ever deletes caches with that prefix. It also re-fills its
precache on the next launch if another app's worker wipes it.

## Spreadsheet import

Settings → Import spreadsheet accepts `.xlsx` or `.csv`. Recognised headers:
Brand, Model (part number), Amount/Qty, Barcode, Item Type, Shelf, Min, Unit,
Notes, and an EXTRAS column (every column to its right is read as extra
barcodes for the same part). Amounts like `114FT` become feet; `-` becomes 0 with
a "verify" flag; shelf values `1–9`, `3-5` (floor under shelf 3) and `RETURN` map to
the seeded locations and anything else can be mapped in the preview.

## Data safety

Local-only storage means deleting the home-screen app, clearing Chrome's site
data or losing the phone deletes the inventory. Use **Settings → Back up**
regularly (the file goes out through the share sheet to Drive/email) and keep the
quarterly Excel exports.

Icons are generated by `tools/gen-icons.ps1` (Windows PowerShell).
